## 目的

使用两台电脑（上位机端和网口调试端），其中网口调试端发送引导信息，用于模拟GPS设备下发的引导信息，测试整个处理流程能否正确传输数据，即网口调试端→上位机端→—>FPGA→DSP→上位机端显示。

## 设备配置

<div class="line-red">网口调试端：</div>

* 协议：UDP
* ip：192.168.1.110
* 端口号：2222
* 发送格式：HEX

发送数据需为106B ,暂定结构体如下

```c++
//导引信息上位机接收数据格式
typedef struct _RecvTrackInfoClass
{
	unsigned int   iDstAddress;         //目的地址

	unsigned int   iTargetNO;           //目标编号    从1开始编号
	unsigned int   iTargetSouceNO;      //目标溯源编号 表征目标分离过程的，填写上一级父目标编号，未分辨出分离过程时该字段填0
	unsigned char  cTraceAttribute;     //目标航迹属性 0x40：单一航迹 0x80：综合航迹 0xC0：遥测数据
	unsigned int   iTraceSource;        //目标航迹主源 综合航迹主源或单站航迹来源的装备识别代码
	int            iTargetPosX;         //目标位置X   单位：1m 取值：-50000000~50000000 CGCS2000坐标系
	int            iTargetPosY;         //目标位置Y   单位：1m 取值：-50000000~50000000
	int            iTargetPosZ;         //目标位置Z   单位：1m 取值：-50000000~50000000
	int            iTargetDis;          //目标距离    单位：1m 取值：-50000000~50000000
	int            iTargetAzi;          //目标方位角   单位：0.1 取值：-120000~120000
	int            iTargetPitch;        //目标俯仰角   单位：0.1 取值：-120000~120000
```

## 测试流程

**确保两电脑网口连接（交换机），且根据注意事项设置ip和放行端口**

1. 上位机端点击“读取引导信息”按钮
2. 网口调试端接收到1024B的回传
3. 网口调试端连续发送106B引导信息
4. 上位机端接收并打印引导信息
5. 加载回波进行下发测试

## 出现问题及其原因

**魔法调试值**是在分配或释放内存期间写入内存的特定值，以便稍后判断它们是否已损坏，并在使用从未初始化的内存中获取的值时使其清晰可见。内存通常以十六进制表示，因此容易记住的重复值或十六进制值很常见。更多请见[Magic number (programming)](https://http://en.wikipedia.org/wiki/Magic_number_(programming))


| Code       | Description                                                                                                           |
| ---------- | --------------------------------------------------------------------------------------------------------------------- |
| `CCCCCCCC` | 被Microsoft的 C++ 调试运行时库和许多 DOS 环境用来标记未初始化的堆栈内存。是 x86 处理器上INT 3调试断点中断CC的操作码。 |
| `CDCDCDCD` | 被Microsoft的 C/C++ 调试 malloc() 函数用来标记未初始化的堆内存，通常从返回HeapAlloc。                                 |
| `BAADF00D` | "Bad food"，微软的调试 HeapAlloc()用它来标记未初始化的分配堆内存。                                                    |
| `DDDDDDDD` | MicroQuill 的 SmartHeap 和 Microsoft 的 C/C++ 调试 free() 函数使用它来标记已释放的堆内存。                            |

```apache
E:\radar8V18\mwRadarCtrl\DataLoadOpDlg.cpp(1373) : atlTraceGeneral - 使用网络接收数据: 距离=-842150451, 方位=-842150451, 俯仰=-842150451
E:\radar8V18\mwRadarCtrl\DataLoadOpDlg.cpp(1401) : atlTraceGeneral - 发送数据: 帧头=0x3412, 距离=CDCDCDCD, 方位=CDCDCDCD, 俯仰=CDCDCDCD
```

点击"加载开始"按钮时，创建了一个空的 CRecvGuideInformation 对象，这个对象的 m\_RecvTrackInfo 指针存在，但数据是未初始化的，所以 if 条件 m\_RecvGuideInformation->m\_RecvTrackInfo 为真，但数据无效，即使点击"读取引导信息"按钮创建了正确的网络接收对象，但 GuideSendThreadProc 中的 pDlg->m\_RecvGuideInformation 仍然指向第一个空对象，**导致的原因是以前测试一个引导信息随着波形参数通过串口传输建立了空的引导信息对象**。
